# 路线图：从「证明自己没坏」到「证明自己有用」

> 写于 2026-11-23。本文件是**执行计划**，不是设计推演。
> 判据：每一项都有可执行的验证命令，做完就打勾，不靠「感觉完成了」。

## 这份计划要解决的问题

审查发现：仓库 23 条未结项里，**8 条是修自检机器自己**的缺陷。
而产品的核心主张——「用户一次给到需求便一次做完」——**从来没有被测量过一次**。

继续修这些，循环会继续发散。所以这份计划按「先让核心机制真的生效，再让价值可测」排序。

## 一个必须先说的架构判断

用户提出：「不加架构的前提是架构是对的」。

本会话的实测数据回答了它：

| 事实 | 数字 |
|---|---|
| 主线程（Hub）在本会话犯的错 | **7 次** |
| 其中被 Spoke（子 Agent）用可复现证据抓住 | **5 次** |
| 被用户抓住 | 1 次 |
| 自己后来发现 | 1 次 |

**Hub 出错 → Spoke 用证据打回 → Hub 修正。这条链路是真的在起作用。**

但有一个具体的洞：**Hub 的错误里有一半是「事实类断言」（说了一个数字/一句话），
而现有的门禁不核 Hub 自己**——验收门核 Spoke 的交付物，红队攻击 Spoke 的结论，
**没有任何角色被派去核主线程说过的话**。

这不是「Hub-and-Spoke 错了」，是**Hub 自己不在验证范围内**。

## 目标 1 · 让「失败」真的可被判（P0）

**为什么最优先**：`deliverVerdict()` 有 39 条测试但没有调用点，`forbiddenContext`
的覆盖没有消费者。**验收门和上下文隔离现在都是纸面的。**
一个没有调用点的门，与不存在同形（DF-042 的原始形态）。

| 项 | 现状 | 完成判据 |
|---|---|---|
| 1.1 `deliverVerdict()` 接进真实链路（DF-080） | 纯函数 + 39 测试，零调用点 | `SKILL.md` Phase E 有一处真的调用它；有一条测试证明「验收 PASS + 红队阻断 → 不可交付」在真实链路里成立 |
| 1.2 `forbiddenContext` 覆盖生效（DF-079） | frontmatter 可覆盖，但 `checkPromptSpec` 读冻结表 | 给 executor 加 `forbiddenContext` 覆盖后，`independence` 判 `false`；负向测试守着 |
| 1.3 **Hub 自述核验**（新增，DF-082） | 无 | 有一个叶子 Spoke 角色 `oversight-verifier`，职责是核主线程本轮说过的每个可核事实；有一条硬门检查证明它在 SKILL 里被派发 |

**1.3 的设计约束**（防止它变成又一个纸面的门）：
- 它是**叶子**，无 `Agent` 工具（深度恒 1 不变）
- 它只核「可机械验证的断言」：数字、文件路径、命令输出、`grep` 结果。
  不核「判断」——判断没有对错可判。
- 它的输入是**主线程本轮输出的原文**，不是主线程的自我总结。

## 目标 2 · 让「省心」变成数字（P0）

**为什么**：`docs/spec/success-metrics.md` 定义了五个指标，**一个都没在算**。
没有数字，「这个框架有没有用」永远只能靠感觉。

| 项 | 完成判据 | 状态 |
|---|---|---|
| 2.1 至少三个指标能算出真实值 | 给出命令 + 真实输出，不编造 | **部分达成**：新增 `scripts/compute-metrics.mjs`（27 条测试）。算出了 3 个真值：语料级 token/调用（231,056,476 token / 55,656 调用）、C2 4/5、C1 5/5；另有 2 条 `n=2` 的链（标了样本量不足）。**没有一个指标是「完整可算」** —— 与 `success-metrics.md` §6 的判断一致 |
| 2.2 算不出来的明说缺什么 | 写清「要在哪加一行什么记录」，不编公式 | **达成**：三个记录点（`verdict` / `locator` / `usage`）逐条写进脚本的 `gap` 输出与 `success-metrics.md` §6；另发现一个**比 `verdict` 更早**的洞（见 DF-083） |

**本轮的一个意外发现（比原计划的结论更硬）**：
规范指定的任务归属键（`expect.nonce` + 首条 user 消息）在本仓实测 **0/3**，
`observe` 自己跑也是 0/256。真因不是判据错，是 **nonce 不在首条 user 消息里** ——
它在 transcript 中段（byte 288,185），来自子 agent 自己 `Read` 了 `claims.jsonl`。
所以「让指标可算」下一步不是先加 `kind:"verdict"`，而是**先让 nonce 进派发 prompt 正文**。

## 目标 4 · 产品核心缺陷：定义它是什么，或明确不是（P1）

**为什么**：`DF-056`（真实拦截 0 次）、`DF-057`（对诚实停下零杠杆）、
`DF-058`（空脚本能骗过）指向同一件事——

> Stop hook 验的是「你说过要验证的话有没有验证过」，
> **不是**「你说做完了到底做没做完」。

这两件事差别很大，而现在文档按后者宣传、代码实现的是前者。

| 项 | 完成判据 |
|---|---|
| 4.1 明确它到底是哪个 | 写进 README 能力边界，用实测数据支撑 |
| 4.2 如果保留现有定位，修掉「空脚本能骗过」（DF-058） | 空 `exit 0` 脚本不能再让断言通过 |
| 4.3 **不修**的部分写进 `accepted-deviations.md` | 写清为什么不修、代价是什么 |
